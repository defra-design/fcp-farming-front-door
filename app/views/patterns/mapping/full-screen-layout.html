Full-screen map layout

A sidebar and an interactive map that fill the screen below the header.

Open this example in a new tab (opens in new tab)

When to use this pattern

Use it when the map is the main way a user finds or understands their land, and they need a list or summary alongside it. For example, viewing all the land parcels on a business.

When not to use this pattern

Don't use it when the map only supports the page, such as a location shown on a question page or a check answers page. Use a normal page with an inline map instead.

Don't use it for long forms: the sidebar is narrow and scrolls on its own.

How it works

Layout and scrolling

The header sits at the top. Below it, the page is split into a sidebar (one third) and the map (two thirds). The page itself doesn't scroll. The sidebar scrolls on its own, and the map fills its column.

The map area is at least 600px tall. On a short screen the whole page scrolls, and the header scrolls away with it.

There is no footer.

On a phone

At 640px wide or less, the sidebar takes the full width and the map is hidden. The map component shows a "Map view" button instead, which the layout moves into the sidebar's #map-button-slot. The button opens the map fullscreen, and the GOV.UK header and service navigation are hidden while it's open.

The page reloads if the window crosses 640px, so the map is always built for the current screen size. Real users won't notice this, but you'll see it when you resize the window or switch device in browser developer tools.

Loading

A "Loading map" message with a spinner covers the map until it has rendered, while the sidebar shows straight away. The page decides when to hide it, usually once its data is drawn and the map is idle. The spinner doesn't move if the user has asked for reduced motion.

Options

Block or variable Use
mapSidebar Sidebar content. Include <div id="map-button-slot"></div> where the phone "Map view" button should go.
mapScripts The page's own script. It runs after the DEFRA map scripts and map-fullscreen.js.
mapHead Extra <head> content, such as another plugin's CSS or prefetch links.
mapCanvas Replaces the map column. By default it holds #map and the loading overlay.
mapSidebarLabel Accessible name for the sidebar region. Defaults to "Map controls".
mapCenter, mapZoom Where the map starts before the page frames its data. Defaults to [-0.69, 53.39] and 12.

JavaScript

AppMap.fullscreen.init({ interactiveMap }) Moves the "Map view" button into the sidebar and keeps the map sized when the window changes.
AppMap.fullscreen.hideLoading() Fades out the loading overlay. Also call it if loading the data fails, so the overlay isn't left on screen.
AppMap.fullscreen.isMobile() True at 640px wide or less. Use it to decide on map behaviour for phones, such as building the interact plugin.

The styles only apply to pages with the app-map-page class on <html>, which the layout sets. That stops them changing how other pages scroll.

Accessibility

  • The sidebar is a labelled region, so screen reader users can jump to it.
  • The loading message is a status message, so screen readers announce it.
  • The page has no footer, so the cookies and accessibility statement links aren't there. A live service would need them somewhere.

Known issues

  • On a short screen the map's 600px minimum height makes the page scroll, so the header scrolls out of view.
  • Between 641px and 1020px wide, the GOV.UK header's contents are indented further than the sidebar, because GOV.UK's 30px page margin still applies at that width.
