Design history Land summary (v1.2)

Third iteration of a prototype that re-presents the existing land summary customer journey using the Defra interactive mapping component (opens in new tab) (v0.0.22-alpha).

This iteration focused on the land parcel page. We made the land covers on the map interactive, and simplified how they are presented in the map's Key and Layers panels. The same changes were applied to the two historical land parcel views (SX3963 2340 and SX3964 7821). We also added a page that compares a previous version of a land parcel with the current version side by side.

  • view-land-parcel
  • view-land-parcel-compare

Selecting a land cover on the map

In v1.1 a user could click a hedgerow on the map to highlight the matching row in the data column, but land covers were not clickable. We extended the same behaviour to land covers. When a user clicks a land cover on the map:

  • the matching row in the Land covers table is highlighted and its text made bold
  • the land cover is outlined on the map
  • clicking anywhere on the map that is not a land cover clears the selection

Where a hedgerow and a land cover overlap, the hedgerow takes the click. This keeps the existing hedgerow behaviour unchanged and avoids highlighting two things at once.

On mobile, the fullscreen map's touch crosshair can also select a land cover.

Why we used the map's own click handling

The mapping component's interact plugin misses clicks on polygons that cross a vector tile boundary, which happens often when zoomed in to a single parcel. We used the underlying map library's own hit test for land cover clicks instead, which is reliable across tile seams. The selection outline is drawn by the prototype rather than the plugin for the same reason.

Key panel

The Key listed the land cover types under a "Land cover" group heading. As the Key only ever shows land covers and hedgerows, the heading added noise without helping users, so we hid it. The heading is visually hidden rather than removed, so screen reader users keep the grouping.

Layers panel

In v1.1 the Layers panel offered three toggles: Land covers, Land parcel outlines and Hedgerows. Land covers could only be switched on or off as a whole. We changed the panel so that:

  • each land cover type on the parcel can be switched on or off individually
  • a "Land cover" parent checkbox switches all of them together, and is ticked while any type is ticked
  • only the land cover types present on the current parcel are listed, rather than every type the service knows about
  • the individual types are indented under the parent to show the hierarchy
  • the land parcel outline toggles were removed, as the outline is the context for everything else on the page

A user's choices in the Layers panel survive a change of base map. They reset when the user navigates to a different parcel, as the list of types changes with the parcel.

The mapping component does not provide a parent checkbox for a group of layers, so the prototype adds one to the panel. This is a prototype workaround and would need to be raised with the interactive map team for the real service.

Colour tuning tool

The colour tuning tool, introduced in v1.1, gained a "Land cover selected" colour for the outline drawn around a selected land cover. As before, the panel only appears when ?colours is present in the URL.

Comparing land parcel versions

In v1.1 a user could open a historical view of a land parcel, but to see what had changed they had to move between that page and the current version and hold the differences in their head. We added a compare page that puts the two versions on one screen.

The page is reached from a "Compare versions" row in the land parcel's summary table, and from a "Compare with current version" link on the historical view. Both only appear for parcels that have a previous version, currently SX3963 2340 and SX3964 7821.

Layout

The previous and current versions are shown in two columns, each with its own map and, below it, the same Summary, Land covers and Hedgerows tables as the land parcel page. A highlighted panel at the top states the date range of the previous version, and each column repeats its own date so the tables stay level. On small screens the columns stack.

Unlike the land parcel page, which locks the page to one viewport, this page scrolls as a normal document. The two maps sit in fixed-height frames at the top and the tables follow underneath.

Linked maps

Panning or zooming either map moves the other to match, so the user is always looking at the same area of the parcel in both versions. Both maps open already framed on the parcel. Each map keeps its own Key and Layers panels and its own base map choice, so a user can, for example, put the current version on aerial imagery while keeping the previous one on the default style.

Clicking a land cover or hedgerow on either map highlights the matching row in that column's tables, using the same behaviour as the land parcel page.

Marking the differences

The tables mark what has changed between the two versions using GOV.UK tags in the first cell of a row:

  • Added on a current version row with no equivalent in the previous version
  • Removed on a previous version row with no equivalent in the current version
  • Changed on both rows where the same land cover or hedgerow has a different area or length

For a change, the current version's value also carries an up or down arrow showing which way it moved. The arrow appears only on the current side, as an arrow next to the previous value would read as the previous value itself having moved. Screen reader users hear "increased" or "decreased" and the previous value after the current one. The Summary rows are marked in the same way when their totals differ.

Land covers are matched by name, and where a parcel has more than one cover of the same type they are paired in area order. Hedgerows have no stable identity between versions, so they are matched by position in the list. This is good enough for the prototype's two example parcels but would need real identifiers in the live service.

Where the data comes from

The current version is read live from the land covers service, as on the land parcel page. That service only returns the covers that are valid today, so the previous version comes from a snapshot file stored with the prototype. The parcel boundary and hedgerows are fetched once and shown on both sides, as only the land covers differ between the two example versions.

Running two maps on one page

The mapping component is not designed for two instances on one page. Its plugins cache their setup from the first map and re-use it for the second, so the second map would otherwise be built with the first map's layers. The prototype works around this by giving each map its own copy of each plugin and its own set of layer identifiers. This is a prototype workaround and would need to be raised with the interactive map team if the real service needs two maps on a page.
