Design review

The review of v1.0 led us to remove the specific date search, as research had shown it confused users. We assumed users would come to the service knowing the land parcel they were looking for.

We shared v1.0 with the wider team so they could review and give feedback on the designs. We also collated the business requirements, user needs and pain points from a previous workshop.

UI changes

Historical view

We added a historical view for 2 land parcels, SX3963 2340 and SX3964 7821, so users can see a parcel as it was before its latest update.

Current version

  • a link goes to the historical view of the land parcel

Historical version

  • inset text gives the dates the historical view covers
  • a link goes back to the current version of the land parcel

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
Users need to see how a land parcel has changed, which the existing journey doesn't show.
We believe
A historical view of a parcel, with the dates it covers, will help users understand what changed and when.
We'll know if
Participants can find the historical view and identify at least one change on a parcel.
Technical notes

The public API has no historical data, so we obtained historical data for the 2 land parcels from the LMS team.

Header

We redesigned the header to match the rest of the service.

  • the sub navigation has been removed
  • a phase banner has been added
  • the business name, SBI, customer name and a sign out link have been added

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
The v1.0 header didn't match the rest of the service, and didn't show whose land the user was looking at.
We believe
A header that matches the service, with the business and customer details, will help users trust they are looking at the right land.
We'll know if
Participants can say which business they are viewing without help.

Hedgerows

We re-presented the existing hedgerow highlighting. Clicking a hedgerow on the map highlights its data in the data column.

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
Users of the existing service can highlight a hedgerow's data from the map, and v1.0 didn't do this.
We believe
Keeping hedgerow highlighting will help users match a hedgerow on the map to its length.
We'll know if
Participants can match a hedgerow on the map to its row in the data column without help.

Layers panel

We re-presented the existing layer toggles. Users can switch Land covers, Land parcel outlines and Hedgerows on and off.

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
With every layer showing, the map can be hard to read, and the existing service lets users switch layers off.
We believe
Switching layers on and off will help users focus on the land information they need.
We'll know if
Participants find and use the layer toggles when the map gets busy.

Land cover colours

Each land cover type on the map is drawn in its own colour, grouped by kind:

  • greens for grassland and woodland
  • blues for water (drains, rivers, ponds)
  • greys for hard surfaces and roads
  • warmer tones for buildings and farmyards

We chose the palette with a colour tuning tool built into the prototype. It let us try colour combinations for land parcel boundaries and land covers live on the map during design sessions.

Colour tuning tool

  • each map element and land cover type has its own colour picker, plus a slider for the hover tint, and changes apply to the map instantly
  • a chosen palette is remembered in the browser, so it persists between page loads
  • Copy share link produces a URL that reproduces the exact palette, so a combination can be shared with the team for feedback without changing any code
  • Copy palette exports the values as JSON, ready to paste in as the new default once a palette is agreed

The panel only appears when ?colours is in the URL. It is a design and research aid, not part of the user journey.

  • view-land-parcel

In v1.2 the tool gained a Land cover selected colour, for the outline drawn around a selected land cover.

  • view-land-parcel (v1.2)

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
With many land cover types on one parcel, unrelated colours make the map hard to read.
We believe
Grouping colours by kind of land cover will help users read the map at a glance.
We'll know if
Participants can match land cover classifications to areas on the map without help.
