UI changes

Land summary page

The land summary page puts a holding's parcels and the map side by side. Clicking a row in the table or a parcel on the map highlights the parcel in the other.

  • a date input is the entry point
  • summary stats show the number of parcels and the total area
  • a sortable table lists the parcels
  • table rows have a pointer cursor, a hover background and a selected state, kept in sync with the selection on the map

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
The existing journey shows the list of parcels and the map separately, so users have to move between them.
We believe
Showing the parcels and the map together, linked both ways, will help users find and check a parcel.
We'll know if
Participants can find a parcel on the map from the table, and in the table from the map, without help.

Parcel details page

The parcel details page shows a single parcel with its land covers and hedgerows, on the same layout as the land summary.

  • land covers are listed with their count, area and totals
  • hedgerows are listed with their count, length and totals
  • each land cover is drawn on the map as its own dataset

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
Users need to see what a parcel is made up of, not only its boundary.
We believe
Listing a parcel's land covers and hedgerows next to the map will help users check them against what they see.
We'll know if
Participants can match a land cover in the list to its area on the map.

Fill patterns

Land covers on the parcel map have fill patterns over their base colours: cross-hatch, dot, horizontal hatch and vertical hatch. This helps users tell similar land covers apart, and keeps the map readable if printed in black and white.

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
Some land cover colours look alike, and colour alone is lost when the map is printed in black and white.
We believe
Adding a pattern to each land cover will help users tell them apart without relying on colour.
We'll know if
Participants can tell neighbouring land covers apart on screen and on a printout.

Fullscreen map controls

We added controls so users can move in and out of the fullscreen map without losing their place.

  • an Exit button on the parcel map returns the user to the land summary from fullscreen
  • on mobile, the component's open-map button is moved into the sidebar as a Map view button, so it sits with the other controls
  • the GOV.UK header and service navigation are hidden when the map is fullscreen

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
The mapping component's fullscreen mode has no way back to the land summary, and its open-map button sits apart from the page's other controls.
We believe
Clear ways in and out of the fullscreen map will help users move between the map and the data.
We'll know if
Participants can open the map and get back to the land summary without help, on desktop and mobile.

Layout iterations

Map and sidebar layout

Both pages share a fullscreen 2-column layout. Below the GOV.UK header and service navigation, the screen is split between a scrolling sidebar (one third) and the map (two thirds).

On screens narrower than 640px, the map column collapses, the sidebar takes the full width and a Map view button opens the map fullscreen.

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
The existing journey shows the land data and the map on separate pages.
We believe
A single view with the data beside the map, and a toggle between them on mobile, will make it easier to check land information against the map.
We'll know if
Participants can move between the data and the map on desktop and mobile without help.

Default and alternative layouts

We built 2 desktop layouts. They show the same data with the same components; only the column order differs. The default layout is shown under Land summary page and Parcel details page.

Why we changed it

{# Draft hypothesis, written from the existing copy: check before sharing. #}
Problem
We don't know whether users expect the data or the map first.
We believe
Comparing the 2 column orders will show which one users find easier to use.
We'll know if
A usability comparison shows participants completing tasks more easily with one layout.

Reference

What's real and what's mocked

All data is fetched when the page loads from the public RPA WFS endpoints on environment.data.gov.uk (opens in new tab). The prototype holds no data.

Data Source Status
Land parcels RPA:LandParcels: boundaries and area for every parcel on the holding Live
Land covers RPA:LandCovers: land cover polygons within each parcel, with a description and area Live
Hedgerows RPA:HedgeControl: hedgerows associated with a parcel, with a length Live
SBI A single SBI, 106332870, is hardcoded Mocked
Last updated date 1 January 2010 is a placeholder Mocked

Interactive map plugins

  • scaleBarPlugin for a metric scale bar
  • mapStylesPlugin for 3 map styles: Default (Liberty), Satellite and Light (Positron)
  • interactPlugin to select a single land parcel on the map, and deselect it on a click outside
  • datasetsMaplibrePlugin on the parcel map, to draw each land cover type as its own labelled dataset, with the parcel outline on top

Known limitations in v1.0

  • the SBI is hardcoded
  • the date input and WFS query are not yet time-bounded
  • the Last updated date of 1 January 2010 is a placeholder
  • hedgerows are listed in the sidebar but not drawn on the map
  • there are no error or loading messages
  • colour contrast on land cover fills
